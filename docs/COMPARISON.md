# scitrace 与 PaperQA2 的功能对比与缺陷清单

> 本文回答两个问题：**两者在功能与逻辑上差在哪**、**scitrace 有哪些真实缺陷**。
>
> **洁净室声明**：撰写本文时**读取了上游源码**（settings 分组、工具名、分块实现、
> Agent 状态枚举）。代码此前已完成，此次读取不进入任何实现；但它构成了第二次
> 接触，已记入 `docs/PROVENANCE.md` §3。在此之前，scitrace 的实现从未参考上游源码。
>
> 对比数据来自**同一份语料、同一套模型配置**（`openai/deepseek-v4-flash` +
> `multi-qa-MiniLM-L6-cos-v1`）上的实际运行，不是文档对文档的比较。

## 二、功能对比

### 2.1 命令与配置

| 维度 | PaperQA2 | scitrace |
| --- | --- | --- |
| 命令名 | `pqa` | `stc` |
| 子命令 | `ask` / `search` / `index` / `view` / `save` | `index` / `ask` / `search` / `status` / `sessions` / `config` |
| 配置方式 | 单命令 + 约 60 个 `--a.b.c` 点分参数（`pqa --help` 输出约 32 KB） | 命名 profile（`~/.scitrace/settings/<name>.json`）+ 环境变量 + 少量 CLI 参数 |
| 配置优先级 | 命令行 > 命名 settings | **五层**：CLI > 进程环境 > profile > `.env` > 默认 |
| 索引隔离 | 按配置哈希自动命名 | 按**表示配置**指纹命名（不含语料路径——见 SPEC §5.3） |
| 索引状态查询 | 无独立命令 | `stc status`（指纹 / 文献数 / 片段数 / 失败数 / 语料分布） |
| 历史问答 | 会话记录落盘，无检索入口 | `stc sessions search <kw>` |
| 结构化输出 | 无 | `--json`（保证纯 JSON，可管道给 `jq`） |

**判断**：PaperQA 把配置全部暴露为命令行参数，灵活但难以复现（一次实验要靠一条几百字符的命令记录）；
scitrace 用命名 profile 换取可复现性，代价是临时改参数不如前者方便。这属于设计取舍，不是优劣。

### 2.2 分块逻辑（**实质性差异**）

| | PaperQA2 | scitrace |
| --- | --- | --- |
| 算法 | 定长滑窗 | 三级结构感知 |
| 参数 | `chunk_chars=5000`，`overlap=250` | `target_chars=1500`，`max_chars=3000`，`min_chars=300`，`overlap_chars=200` |
| 切分位置 | 按**字符**位置硬切 | 章节 → 段落 → **句子边界**（中英句末标点，含缩写/小数/人名首字母排除） |
| 章节信息 | 无（块内不含所属章节） | 有 `section_path`，跨节合并时用**公共前缀**归属 |
| 参考文献 | 不剔除 | 剔除参考文献区块，**遇到下一个章节标题即恢复收录** |
| 篇章结构 | 不感知 | Markdown 标题、数字编号、罗马数字、中文「第X章」、全大写短行 |

**实测差异**：对同一篇 25 页论文（PaperQA2 原文），PaperQA 的定长切分会把句子拦腰截断；
scitrace 按句边界切分，片段全部以句末标点收尾。反过来，定长切分对**没有标点的文本**
（表格、公式、乱码）更稳——scitrace 需要额外的硬切兜底路径，这条路径有专门测试。

### 2.3 Agent 与工具

| | PaperQA2 | scitrace |
| --- | --- | --- |
| 工具 | `paper_search` / `gather_evidence` / `gen_answer` / `reset` / `complete`（+ `clinical_trials_search`） | `search_literature` / `gather_evidence` / `answer_question` / `reset_scope` / `finish` |
| 终态 | `FAIL` / `SUCCESS` / `TRUNCATED` / `UNSURE` | 上述四项 + **`REFUSED`（拒答是独立终态）** |
| 确定性模式 | `fake` agent（固定工具顺序） | `--mode deterministic`，**字节级可复现**并有测试钉住 |
| 参数容错 | 有重试 | 回灌错误让模型重试，上限可配；超限置 `FAIL` |
| 预算 | 成本**统计** | 成本**闸门**：超限时用已有证据**强制收尾**（而非丢弃工作） |
| 超时 | 有 | 有，且**强制合成在超时作用域之外**——超时也一定拿得到答案 |

**判断**：`REFUSED` 独立成态是有意的。若把拒答并进 `UNSURE`，就无法区分
"系统认为证据不足"与"系统没答完"——而这两者对使用者的含义完全不同。

### 2.4 检索与证据

| | PaperQA2 | scitrace |
| --- | --- | --- |
| 向量库 | numpy + Qdrant（可切换） | numpy（**无 Qdrant**） |
| 融合 | 向量召回 + MMR；tantivy 用于**检索论文** | 4 路策略可切换：`dense` / `dense_mmr` / `hybrid_rrf` / `hybrid_rrf_rerank` |
| 全文索引 | tantivy（论文级） | tantivy（片段级）+ **中文 bigram** |
| 证据筛选 | RCS（LLM 摘要 + 0–10 分） | LLM RCS **或** Cross-Encoder（可切换，构成消融轴） |
| 重排 | 无独立交叉编码器 | Cross-Encoder 重排器（缺后端时**显式报错**，不静默降级） |
| 引用键 | `pqac-XXXXXXXX` | `ev-XXXXXXXX`（确定性派生，可复现） |
| 拒答短语 | `I cannot answer` | `INSUFFICIENT_EVIDENCE` / 「证据不足，无法回答」 |

### 2.5 解析与元数据

| | PaperQA2 | scitrace |
| --- | --- | --- |
| PDF 解析器 | 4 个子包：PyPDF / MuPDF / Docling / Nemotron | pypdf + plaintext（**少 3 个后端**） |
| 多模态 | 支持图片/表格富化（可选） | **不支持**（`Fragment.media` 字段预留） |
| 元数据源 | Crossref / S2 / OpenAlex / Unpaywall | Crossref / S2 / OpenAlex + **本地撤稿快照** |
| 元数据推断 | 用 LLM 从正文推断引用信息 | 只用正文正则提取 DOI/arXiv 编号 |
| 纯文本编码 | 无特殊处理 | **编码探测**（UTF-8/BOM/GB18030/Big5/UTF-16） |
| 领域工具 | `clinical_trials_search` | 无 |

### 2.6 scitrace **确实缺失**的功能

1. Qdrant 向量后端；
2. MuPDF / Docling / Nemotron 解析后端；
3. 多模态（图片、表格富化）；
4. ClinicalTrials.gov 工具；
5. Zotero / OpenReview 集成；
6. Unpaywall 开放获取链接来源；
7. 用 LLM 从正文推断引用信息（scitrace 只做正则提取）；
8. 官方基准（LitQA2）上的分数——scitrace 只有自建边界语料与评测骨架。

### 2.7 scitrace **多出**的功能

1. 中文 bigram 全文索引与中文句边界分块；
2. 中英双语提示词库（含双语拒答识别）；
3. 可切换的检索策略与筛选后端（消融轴）；
4. Cross-Encoder 重排；
5. 预算闸门（超限强制收尾，而非仅统计）；
6. `REFUSED` 独立终态；
7. 本地撤稿快照（不依赖在线端点）；
8. 纯文本中文编码探测；
9. `--json` 结构化输出、`status` / `sessions` 子命令；
10. 机械化的洁净室审计与分层约束校验。

## 三、边界实测：两个系统的行为差异

### 3.1 摄入阶段

| 语料 | PaperQA2 | scitrace |
| --- | --- | --- |
| 24 份混合格式文件（含 23 个 `.txt`/`.md`） | **每次运行都以退出码 1 结束** | **一次通过：23 新增 / 0 失败 / 513 片段 / 19.4 s** |
| `07_headers_only.md`（只有标题） | `ValueError: This does not look like a text document`，**中断整个索引构建**，需 `disable_check` 才能跳过 | 正常摄入（0 片段，状态 ok） |
| Semantic Scholar 限流 429 | 异常向上传播，**索引构建失败**；需要反复 resume 才能推进（实测 3 轮 resume 后 14 文件 / 6 成功） | 重试 3 次后**降级为"该来源无贡献"**，其余全部照常完成 |
| 空文件 / 纯空白 / 整篇参考文献 | — | 状态 ok、0 片段（不崩溃） |
| 同 DOI 两个文件 | — | 正确归并为 1 篇并上报 |

**这一组对比最能说明问题**：同一份语料、同一套模型、同样的上游限流，
PaperQA 的索引构建无法完成，而 scitrace 一次通过。差异不在算法，而在
**降级策略**——scitrace 的元数据来源在实现内部就把"失败"消化成 `None`，
组合层不必逐来源写 try/except（SPEC §3.5）。

### 3.2 问答阶段（scitrace，8 个边界探针）

| 探针 | 结果 | 评价 |
| --- | --- | --- |
| 中文可答问题 | `SUCCESS`，1 处引用，50 字 | ✓ |
| 含 Emoji 的问题 | `SUCCESS`，1 处引用，180 字 | ✓ |
| 语料外问题 | `REFUSED`，0 引用 | ✓ 正确拒答 |
| 空问题 | `REFUSED`，**0.0 s、不调用 LLM** | ✓ |
| 纯空白问题 | `REFUSED`，**0.0 s、不调用 LLM** | ✓ |
| 纯符号问题 | `REFUSED`，2.9 s | ✓ |
| 1500 字超长问题 | `UNSURE`，21 字，无引用 | ⚠ 见下 |
| **英文可答问题** | **`REFUSED`，0 引用** | ⚠ 见 §4.4：**不是跨语言问题**，是该语料本身没有相关内容 |

> PaperQA2 在同一语料上的逐题结果未能取得：其索引构建始终以退出码 1 结束，
> 无法进入问答阶段。因此 §3.2 与 §3.3 只有 scitrace 一侧的数据。
> 这一点本身即为结论的一部分。

### 3.3 scitrace 的边界行为清单

| 边界 | 行为 | 是否需要改进 |
| --- | --- | --- |
| 空/纯空白/无正文文件 | 摄入成功但 0 片段，计入"新增" | 低。可考虑单列"空文档"计数 |
| 纯符号问题 | 检索返回空 → 不调用 LLM → 拒答 | 否 |
| 超长问题（1500 字） | 得到 21 字无引用答案 → `UNSURE` | 中。无引用的答案应更明确地标记 |
| 无元数据的语料 | 引用渲染为 `(anonnd<文件名> ...)` | 低。这是"垃圾进垃圾出"，但可改善：从首页文本提取标题 |
| 同 DOI 多文件 | 归并并上报 | 否 |

## 四、通过边界测试发现的 scitrace 缺陷

### 4.1 混合格式语料完全无法摄入（已修）

默认配置 `ingest.parser="pypdf"` 下，一份含 23 个 `.txt`/`.md` 的语料**一篇都索引不进去**，
全部报 `解析器 'pypdf' 不支持文件 xxx.txt`。

根因：SPEC 把 `parser` 定义为"**PDF** 解析后端名"，而实现把它当成了"所有文件的强制解析器"
传给 `select_parser(preferred=...)`——后者在"首选解析器不支持该文件"时报错而不回退。
那个严格行为是为"配了 pymupdf 却静默用了 pypdf"这类误配置设计的，语义不同。

**为什么此前没发现**：全部测试要么是纯 PDF，要么走不带 `preferred` 的自动选择路径。
混合格式是真实使用中最常见的情形。

**修复**：`preferred` 只在其声明的格式内生效，其他格式走自动选择。
已加回归测试（PDF + txt + md 共存）。

### 4.2 短小节产出大量碎片（已修）

`min_chars` 合并被限制在"同 section 内"，而相邻小节的 `section_path` 各不相同，
于是一份由 48 个"小节标题 + 一句话正文"组成的文档产出 **48 个 42 字符的碎片**。
全语料 8.9% 的片段不足 100 字符，最短 4 字符。

42 字符的片段作为证据几乎无用，还会让检索结果被碎片刷屏。

**修复**：允许跨章节合并，但用**公共前缀**作为归属——既不产碎片，
也不谎称内容属于其中某一节。**碎片 50 → 2**。

### 4.3 摄入后元数据快照不刷新（已修）

`services.sources` 是构造时从磁盘读的快照。"同一进程内先摄入再提问"会拿着空元数据
渲染引用（表现为引用全是 `unknown`，而索引里其实有完整信息）。
CLI 每次命令重建 services 掩盖了这个陷阱，边界测试用同一进程跑才暴露。

### 4.4 跨语言检索：**修正后的结论**（初版判断有误）

#### 我最初的说法

> "嵌入模型 `multi-qa-MiniLM-L6-cos-v1` 是纯英文的，跨语言检索失效，
> 中文语料用英文问题检索不到，最终走向误拒。换成多语言模型即可修复。"

#### 验证过程与结果

**第一层：嵌入对齐测量（成立）**

| 模型 | 中文句 ↔ 其英文译文 | 中文句 ↔ 无关中文 |
| --- | --- | --- |
| `multi-qa-MiniLM-L6-cos-v1` | **+0.0733** | +0.5271 |
| `BAAI/bge-small-zh-v1.5` | +0.5767 | +0.2785 |
| `intfloat/multilingual-e5-small` | +0.8619 | +0.8079 |

测量本身没问题：基线模型确实**没有跨语言对齐**（译文比无关句更不相似）。
但"嵌入没有对齐"**推不出**"检索会失败"——检索是在小语料上的**排序**问题，
语言造成的分数惩罚未必把结果挤出 top-k。

**第二层：同一目标、同一语义，只改提问语言（决定性）**

语料：PaperQA2 原文（英文，41 片段）。三个目标各对应一个具体事实：

| 目标 | 基线 EN / ZH | bge-small-zh EN / ZH | e5-small EN / ZH |
| --- | --- | --- | --- |
| Grobid 解析章节表格 | 1 / **9** | 1 / **2** | 1 / 7 |
| ContraCrow 矛盾检测 | 1 / **6** | 2 / **1** | 1 / 2 |
| 被引数 | 2 / 2 | 4 / 1 | 1 / 3 |
| **中文问平均排名** | **5.7** | **1.3** | 4.0 |

#### 修正后的结论

1. **"跨语言检索失效"是错的。** 基线模型用中文提问仍能把目标排进前 10
   （9 / 6 / 2），甚至前 5 两次。它**存在明显的语言惩罚**（英文第 1 名 → 中文第 9 名），
   但没有"检索不到"。
2. **换模型确有可测量的收益**：`bge-small-zh-v1.5` 把中文提问的平均排名从 **5.7 提到 1.3**，
   代价是英文侧从 1.3 略降到 2.3。这是"更合适"，不是"从不能用变成能用"。
3. **`multilingual-e5-small` 在中文侧反而不如 `bge-small-zh-v1.5`**（4.0 vs 1.3），
   尽管它在嵌入对齐测量上数字更好看（0.862 vs 0.577）。**嵌入相似度的绝对值
   不能预测检索排名**——这是本次验证最实用的一条教训。
4. **初版把"误拒"归因于跨语言也是错的。** 那个误拒发生在边界语料上，
   根因是那份语料本身是**合成的填充文本**（同一句重复 40 次、HTML 占位符等），
   没有任何内容真正回答了那个问题。嵌入模型只是正确地反映了"这里没有相关内容"。
   证据：把无关英文 filler 与含「证据抽取」的中文放在一起比较，
   `bge-small-zh-v1.5` 给前者的分数（+0.649）反而**高于**后者（+0.538）——
   在统计垃圾语料上，模型匹配的是"体裁"而不是"内容"。

#### 可执行的建议（已按修正后的证据调整）

| 场景 | 建议 |
| --- | --- |
| 语料以中文为主 | 换 `BAAI/bge-small-zh-v1.5`：中文提问排名显著改善，代价是英文侧小幅下降 |
| 中英并重 | `intfloat/multilingual-e5-small`：英文几乎无损，中文也有改善（但不如纯中文模型） |
| 以英文为主 | 保持 `multi-qa-MiniLM-L6-cos-v1`（PaperQA 的选择）：英文最优，中文仍可用 |

**注意**：换嵌入模型会改变索引指纹（SPEC §5.3），必须重新摄入。

#### 方法论反思

这次验证暴露了我在初版对比里的一个推理跳跃：**从"嵌入空间的性质"
直接跳到"端到端系统的行为"**。中间隔着检索、筛选、阈值、拒答判定四层，
每一层都可能改变结论。第一层的测量是对的，但结论越界了。

同样的错误也出现在我最初的"跨语言检索实验"上：我用了一份**自己造的、
有缺陷的语料**（目标片段是同一句重复 40 次——重复本身会稀释嵌入，
实测相似度从 +0.538 掉到 +0.462），而且第一版测试的判据词（`"tool"`、
`"contradiction"`）在论文里到处都是，前 10 名必然命中——那个实验**没有区分度**，
却几乎让我确认了一个错误结论。

### 4.5 已知但刻意保留的行为

| 行为 | 理由 |
| --- | --- |
| 同 DOI 两文件共用 `source_key` 时跳过旧片段清理 | `remove()` 以 `source_key` 为单位，精确到文件级需要端口支持按 `fragment_id` 删除。已写入 SPEC §3.1 |
| `Fragment.media` 恒为空 | 多模态属首版非目标 |
| 成本恒为 0（`deepseek-flash` 不在 litellm 价格表） | 记 0 并**告警一次**，而非让整次问答失败 |

## 五、PaperQA2 在本次实测中暴露的问题

1. **对"不像文本文档"的文件硬失败**：`07_headers_only.md` 触发 `ValueError`，
   中断整个索引构建流程。批量摄入时，一个异常文件会拖垮整批。
2. **元数据源限流会导致索引构建失败**：Semantic Scholar 429 的异常向上传播，
   每次运行都以退出码 1 结束；实测需要 3 轮 resume 才推进到 14 文件 / 6 成功。
   本项目在同一限流下通过降级正常完成。
3. **定长滑窗分块会截断句子**：对正常论文，块边界落在字符位置而非句边界。

> 这三点是**实测观察**，不代表 PaperQA2 的整体质量——它在多模态、解析器生态、
> 期刊质量分级、LitQA2 基准成绩等方面明显强于 scitrace（见 §2.6）。

## 六、结论

**功能上**：scitrace 覆盖了 PaperQA2 的核心链路（解析 → 元数据 → 分块 → 双索引 →
Agent 检索 → 证据筛选 → 带引用答案 → 拒答），在**中文支持、检索策略可插拔、
预算闸门、降级健壮性、配置可复现性**上更强；在**多模态、解析器生态、
领域工具、基准成绩**上明显更弱，属于首版范围的刻意裁剪（SPEC §1.2 已声明）。

**逻辑上**：本次边界测试发现的 4 处缺陷中，3 处已修复并加了回归测试。
第 4 处（跨语言检索）经**独立验证后被推翻**——详见 §4.4：基线模型确实缺乏跨语言
嵌入对齐（译文 +0.073 vs 无关句 +0.527），但检索并未失效（中文提问的平均排名
5.7，仍在 top-10 内）。换 `bge-small-zh-v1.5` 能把平均排名提到 1.3，属于
"更合适"而非"从不能用变成能用"。初版把误拒归因于跨语言，方向错了。

**最有价值的单一发现**：PaperQA2 在混合格式语料 + 上游限流下**索引构建无法完成**，
而 scitrace 一次通过。差异来自降级策略的设计位置——把"失败"在适配器内部消化掉，
而不是让组合层逐来源处理。
