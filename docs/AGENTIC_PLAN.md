# Agentic 模式改进方案（v2，基于失败证据重写）

> 本文件替代 SPEC §4 中对 agentic 模式的**性能假设**。
> SPEC §4 的接口、状态机与兜底策略仍然有效，但其"成本来自历史增长"的预判
> 已被实测否定（见 `docs/EXPERIMENTS.md` 实验六 6.5、实验十四 14.2）。
> SPEC 是冻结规范，本文件只描述**改进路线**，不改动规范正文。

## 0. 一句话总结

**把 agentic 从"agent 反复试探"改成"一次性规划 + 固定预算装配 + 结构化停止判据"。**
前者每一步都要重发上下文并重跑筛选，成本随试探次数线性增长且质量不稳定；
后者把不确定性集中到**一次**规划调用上，其余步骤变成确定性的预算内装配。

## 1. 实测诊断（改进的唯一依据）

### 1.1 成本模型

```
总成本 ≈ gather 轮次 × retrieval.k × 单次筛选开销(≈1400 tokens) + agent 自身开销(11%)
```

| 事实 | 数值 | 来源 |
| --- | --- | --- |
| agent 自身占比 | **11.3%**（历史仅 322→1,710 tokens） | 实验十四 14.2 |
| 工具内部筛选占比 | **83.2%**（66 次调用 / 7.2 万 tokens 量级） | 同上 |
| 单次筛选开销 | 693 prompt + **454 completion** | 实验六 6.2 |
| 每题 LLM 调用 | 15–76（同题方差极大） | 实验七 7.2 |
| 固定开销（系统提示词 + 5 个工具 schema） | 926 tokens/次调用，12 次共约 11k | 实验十四 14.1 |

**推论**：压缩历史、压缩系统提示词、压缩回灌观测**都不是杠杆**——
它们加起来只占 11% 的一部分。唯一有效的方向是**减少筛选调用次数**，
即减少 `轮次 × k`。

### 1.2 五个失效模式（按严重度）

| # | 失效 | 实测 | 根因（已定位/待验证） |
| --- | --- | --- | --- |
| **F1** | **对可回答问题过度拒答** | a24 上 **2/3 次拒答**，deterministic 3/3 答对 | `dense_mmr` 把正确文献排到第 3（片段相似度 −0.004/−0.044/−0.081，即"不相关"），无关文献排第 1；叠加 `min_relevance=5` 偏严 |
| **F2** | **循环跑长后被截断** | 跨论文层 **33% TRUNCATED** | `max_steps=12` 硬截断 + 强制收尾；提示词层的停止催促**已被实测证明无效**（观测里已含明确停止指引，agent 仍连调 7 次） |
| **F3** | **无效试探轮次** | 一次运行 12 次 `gather_evidence`，其中 5 次无新增证据 | agent 反复换措辞重试；预过滤后这些轮次不再付筛选费，但仍消耗 agent 决策与上下文 |
| **F4** | **证据集无界增长** | 每轮追加，无上限 | 合成输入随证据条数膨胀；合成因推理 token 吃光预算而整体失败（233 次中 1 次） |
| **F5** | **成本结构性偏高** | agentic ¥0.098/题 vs deterministic ¥0.032/题 | 轮次 × k 的筛选调用；**已证明无法降到基线 1/3**（实验十八） |

### 1.3 已排除的方案（不必重试）

| 方案 | 实测结论 |
| --- | --- |
| 历史压缩 | SPEC 要求已实现，但 agent 历史仅 1.7k，**永不触发**，非杠杆 |
| 压缩旧助手消息 | agent 每步输出仅 49–74 字符，**假设不成立** |
| `cross_encoder` 筛选后端 | 省 **5%**，正确率掉 **11pp**，延迟更长 |
| 提示词催促停止 | 已含明确指引，agent 仍无视 |
| `retrieval.k=3` | 留出集上覆盖率 **−19pp**（调参集上的"又便宜又更好"是测试集选择假象） |

## 2. 主流方法对照

| 本项目的失效 | 主流做法 | 代表工作 |
| --- | --- | --- |
| F3 反复试探 | 查询分解/规划，一次分解多子查询 | Agentic RAG Survey 的 planning 类；[Agentic RAG Survey (arXiv 2501.09136)](https://axi.lims.ac.uk/paper/2501.09136)（**已在本项目语料内**） |
| F4 证据集膨胀 | **固定预算装配**：替换而非追加，抑制上下文稀释 | [Replace, Don't Expand: Fixed-Budget Evidence Assembly](https://www.semanticscholar.org/paper/Replace%2C-Don't-Expand%3A-Mitigating-Context-Dilution-Lahmy-Yozevitch/9b98f4ebbdeecfa8bcbeac855526919c727c892b) |
| F2 停止不可靠 | **结构化停止判据** + 检索缩减 | [When Should Multi-Round RAG Stop?](https://arxiv-org.ezproxy.obspm.fr/html/2608.13237v1) |
| F5 调用次数多 | 减少调用与 token 开销 | [CompactRAG](https://dl.acm.org/doi/abs/10.1145/3774904.3792512)；[PEARL: Learned Orchestration](https://ieeexplore.ieee.org/document/11619898) |
| F1 误拒 | 混合检索 + 重排 + **校准的拒答阈值** | [hybrid retrieval + calibrated refusal threshold 的工程实例](https://github.com/ArminShirzad/tutor-rag) |

> **语料内的方法论文**（`my_papers/` 已摄入，可直接检索对照）：
> Agentic RAG Survey、A-RAG（层次化 agentic RAG）、Self-RAG（自省 token）、
> Corrective RAG（检索评估器 + 纠正动作）、RAP（检索增强规划）。

## 3. 改进方案

### 批次 1 — 参数级（低风险，直接打最严重的质量缺陷与最大成本项）

#### 改进 A：筛选摘要长度上限（针对 F5，纯降本）

- **做法**：筛选提示词要求摘要不超过约 100 词。当前实测 **454 completion tokens**，
  且摘要只作为证据文本使用，不需要那么长。
- **预期**：completion 454 → 约 150–200，单次筛选 1147 → 约 850 tokens；
  筛选占 83%，换算总成本约 **−25~30%**。
- **证伪**：同批题质量指标不降。若降，说明摘要长度承载了必要信息。
- **风险**：低。可随时调回。

#### 改进 B：修检索排序 + 校准拒答阈值（针对 F1，最严重的质量缺陷）

- **做法**：
  1. `retrieval.strategy`：`dense_mmr` → `hybrid_rrf`。**已实测**：a24 查询下
     GraphRAG 论文从第 **3** 名提到第 **1** 名（前三名全是它）。
  2. `screening.min_relevance`：5 → 2 或 3（做扫描）。
- **预期**：a24 的过度拒答消失；这类"实体归属"问题在留出集上也应改善。
- **证伪**：① a24 拒答率；② **库外题的拒答率不能下降**——放宽阈值最危险的后果
  就是开始编造。`hallucination_rate` 在实验十三修复后已是**真实测量**，正好用上。
- **风险**：中。放宽阈值引入噪声证据，可能抬高幻觉率。**必须两个指标一起看。**

### 批次 2 — 结构调整（中等风险）

#### 改进 C：证据集固定预算装配（针对 F4）

- **做法**：给证据集设**条数上限**（建议 12）；新证据按相关性打分**替换**最低分的，
  而不是无限追加。合成时始终只看预算内的证据。
- **预期**：合成输入聚焦 → 上下文稀释减轻；降低"推理 token 吃光预算导致合成失败"的概率。
- **证伪**：答案覆盖与行为正确率不降；合成失败标记消失。
- **风险**：中。早期低分但关键的证据可能被换出——这正是"替换策略"要调的地方
  （按分数替换 vs 按"子查询配额"替换）。

#### 改进 D：结构化停止判据（针对 F2）

- **做法**：不再依赖 `max_steps` 硬截断，改为每步用**廉价判据**判断是否该停：
  本轮新增证据数、证据集最高分、子查询是否处理完。命中即**主动收尾**，
  而不是撞上限后被强制合成。
- **预期**：TRUNCATED 率从 **33% → 接近 0**。
- **证伪**：TRUNCATED 率下降 **且** 质量不降（防止"过早停止"）。
- **风险**：中。判据误判会导致过早停止。必须有"最低证据量"下限保护。
- **注意**：单纯把 `max_steps` 调大不是方案——上游默认不限步数、
  靠提示词引导结束，而**提示词引导在本项目已被实测证明无效**。

### 批次 3 — 架构变更（最大收益，最大风险，需单独决策）

#### 改进 E：一次性查询分解（针对 F3、F5，成本结构性下降）

- **做法**：agentic 开始时用**一次** LLM 调用把问题分解成 2–4 个子查询；
  对每个子查询执行一次"检索 + 筛选"（可并行），然后合成。
  agent 不再是"试探者"，而是"规划者 + 装配者"。
- **预期**：轮次从 4–8 降到 1（规划）+ N（子查询）。筛选调用
  从约 66 次降到约 30 次（N=3、k=10）。
- **关键论点**：**这不必牺牲召回**——原来那些"换措辞重试"的轮次检索到的
  大多是**重叠**片段（预过滤日志可证），把它们换成不重叠的子查询，
  是在相同预算下提高证据多样性。
- **证伪**：① 证据集对参考答案片段的覆盖率；② 最终质量指标；
  ③ 筛选调用次数是否真降。
- **风险**：高。分解质量取决于单次调用；多跳问题分解错误会连锁失败。
  **这一条改变了 agentic 的性质**（从 ReAct 式迭代变成 plan-and-execute），
  属于架构选择，应单独评估后再做。

## 4. 执行纪律（吸取本次三类测量陷阱的教训）

本项目的失败有一半不是实现错误，而是**测量错误**。以下为强制纪律：

| 陷阱 | 实例 | 纪律 |
| --- | --- | --- |
| 查询集太简单 → 错误符号 | 实验一 | 调参集必须含"易混淆"负样本 |
| 指标结构性恒为 0 | 实验十三 | 新指标必须有**判据存在性测试** |
| 在测试集上调参 → 不可复现 | 实验十六 | **任何调参只在调参集做；留出集只用于最终验证，全程不参与选择** |

其他约束：

1. **一次只改一项**，否则无法归因（本次的 k 实验就是靠单变量才定位到取舍曲线）。
2. **成本按 token 计**，不按金额——避免计价配置/币种带来的第二类错误。
3. **每项改动都要有反向验证有效的回归测试**（临时还原旧行为必须让测试失败）。
4. **报告必须同时给调参集与留出集**，只报一个视为未完成。
5. 每批结束后跑 `tools/similarity_audit.py`，最长公共 token 连续片段必须保持 **0**。

## 5. 验收标准

| 指标 | 现状 | 批次 1 目标 | 批次 2 目标 |
| --- | --- | --- | --- |
| 行为正确率（留出集） | 1.000 / 0.963（ag / det） | 不降 | 不降 |
| 答案覆盖（留出集） | 0.952（agentic k=10） | 不降 | 不降 |
| a24 类过度拒答 | 2/3 拒答 | **≤1/3** | 0 |
| TRUNCATED 率 | 33%（跨论文层） | 不恶化 | **<5%** |
| 幻觉率（库外题） | 0/8 | **0/8（硬约束）** | 0/8 |
| 每题 token | 基线 100% | **≤70%** | ≤55% |

> **明确不再作为目标**：
> - "agentic token 降至基线 1/3"——已经测量证明不可达（实验十八 18.3），
>   且同一系统的 deterministic 本来就在 1/3 以内且有更好的质量/成本比。
> - 引入 RL 训练（Search-R1 类）：本项目是推理期系统，无训练基础设施，
>   且质量收益与工程量不成比例。
> - 多智能体（检索/批判/回答分离）：成本翻倍，本项目没有任何证据支持它能解决 F1–F5。

## 6. 与原创性主张的关系

批次 1 的两项（改进 A、B）**都能由本项目自己的测量独立推出**：
A 来自实测的 454 tokens/片段 × 66 次调用；B 来自 a24 上 2/3 次过度拒答的实测。
上游 PaperQA2 的取值（摘要"约 100 词"、阈值 1/10）只是**佐证**，
因此采纳时来源应写为"由本项目测量得出"，原创性主张不受影响。

批次 3 的改进 E 更接近一次架构借鉴（与上游"提示词引导终止、不限步数"的思路同源）。
若采纳，`scitrace` 在 agentic 区域的定位需从"洁净室重写"相应说明，
**该决定须由用户做出**（见 `docs/PROVENANCE.md` E3）。
