# 开发流程与原创性证据（PROVENANCE）

本文件记录 `scitrace` 的开发流程、隔离纪律、**污染事件**与验证手段。
它的目的是让"本项目代码为独立编写"这一主张**可被第三方核查**，而不是一句自述。

## 2. 洁净室纪律（本项目的实际标准）

严格的"洁净室"（clean room）要求**两个人**：一人读原始实现写规格，另一人只读规格写实现，
两人之间无信息泄漏。本项目是单人开发，**无法满足该标准**。因此我们采用一个**可核查的
弱化标准**，并如实标注其边界：

> **标准**：独立重实现（independent reimplementation）。
> 全部代码与文本由本项目作者编写，**未复制**上游任何受著作权保护的表达；
> 作者对上游的接触范围被完整记录（§3），并通过机械化审计（§4）验证无文本复制。

### 纪律条款

| # | 条款 |
| --- | --- |
| R1 | `docs/SPEC.md` 是实现的唯一依据。规格冻结后，实现阶段不再阅读上游源码 |
| R2 | 上游仓库与本项目仓库**不放在同一工作目录**（本机上分别为 `/home/wby/PaperQA` 与 `/home/wby/MyPaperQA`） |
| R3 | 绝不从上游复制代码片段、注释、docstring、Prompt、文档句子——包括"改写式搬运" |
| R4 | 不引入上游及其同族依赖；不使用上游标识符（`PaperQA` / `pqa` / `pqac`） |
| R5 | 每次提交前运行 `tools/similarity_audit.py`，报告入库（`docs/AUDIT.md`） |
| R6 | 发现任何疑似污染，立即登记到 §3，并重写相关实现 |

## 3. 污染记录（Contamination Log）

**这是本文件最重要的一节。** 如实记录接触范围，才能让外部评估者判断风险边界。

### E1 — 需求分析阶段的结构性勘察（2026-02）

在编写 SPEC 之前的需求分析中，为评估可行性与工作量，执行了以下**只读**操作：

| 操作 | 接触内容 | 风险 |
| --- | --- | --- |
| 目录/文件枚举、行数统计 | 文件路径、模块划分、代码规模 | 低（事实性信息） |
| `git remote -v` / `git log` / `git status` / `git diff` | 仓库元信息、作者本地的中文注释改动 | 低 |
| `grep "^(class\|def\|async def)"` 于 `docs.py`、`types.py`、`settings.py`、`llms.py`、`readers.py`、`utils.py`、`agents/*` | **类名、函数名、方法签名清单** | 中（接口命名可能被无意识沿用） |
| 读取 `core.py` 第 1–120 行**全文** | JSON 容错解析函数的实现细节 | **高** |
| 读取 `prompts.py` 第 1–60 行**全文** | 若干 Prompt 字符串原文 | **高** |
| 读取 `LICENSE`、`CITATION.cff`、`pyproject.toml` | 许可与依赖清单 | 低 |

**结论**：本次项目**不是**严格洁净室，`core.py` 与 `prompts.py` 的接触构成实质污染风险。

### 缓解措施（已执行 / 待执行）

| 风险面 | 缓解 | 状态 |
| --- | --- | --- |
| Prompt 文本 | `prompts/` 下的全部提示词从零重写，采用本项目自己的哨兵短语、引用格式与说明顺序；哨兵 `NOT_APPLICABLE` / `INSUFFICIENT_EVIDENCE` 与上游表述无关 | 待实现（M5） |
| JSON 容错解析 | SPEC §3.7 规定了本项目自定的四步降级链（直接解析 → 剥围栏 → 剥思维链 → 括号配平截取 → 正则提取），**不使用**上游的正则改写策略 | 待实现（M4） |
| 接口命名 | SPEC §2.1 采用自定术语（`Source`/`Fragment`/`Evidence`/`Session`/`EvidenceKey`），与上游命名体系不同 | 已完成 |
| 无意识重叠 | `tools/similarity_audit.py` 逐提交扫描 8-gram / 字符串字面量 / 逐行复制 | 脚本已就绪（见 `docs/AUDIT.md`） |
| 依赖与标识符 | 审计脚本第 4 项硬性阻断 | 已就绪 |

> 一份如实记录的接触清单 + 一份通过阈值的机械审计，比一句"我完全没看过"更可信——
> 后者既无法验证，也不是事实。

## 4. 机械化验证

### 4.1 审计脚本

```bash
python tools/similarity_audit.py \
    --target /home/wby/MyPaperQA \
    --reference /home/wby/PaperQA \
    --report docs/AUDIT.md
```

比对基准通过 `git -C <reference> show HEAD:<path>` 读取上游**跟踪文件的原始版本**，
从而排除作者本地的中文注释改动与未跟踪文件。

### 4.2 检查项与阈值

| # | 检查项 | 阈值 | 意义 |
| --- | --- | --- | --- |
| 1a | **最长公共 token 连续片段**（决定性判据） | 任一文件 < 25 token（**不受文件大小豁免**） | 无整段搬运。连续几十个 token 逐字一致无法用"框架趋同"解释 |
| 1b | token 8-gram containment（辅助判据，含注释与字符串） | 整体 ≤ 2%；单文件 ≤ 5%，且 n-gram 总数 < 300 的小文件豁免 | 无大规模代码/注释搬运；超标但无长片段者列为待人工复核 |
| 2 | 逐行精确复制（≥12 字符的非空行） | 实质性行 = 0，且最长行号对齐片段 < 5 行 | 无逐行复制 |
| 3 | 字符串字面量相似度（≥20 字符，`difflib`） | 相似度 < 0.6，或实际匹配字符数 < 32 | 无 Prompt 搬运；事实性短串（DOI/URL）不误报 |
| 4 | 禁用依赖与标识符 | 0 命中（独立性守卫工具文件豁免，豁免范围见报告） | 无依赖/命名污染 |
| 5 | 与上游资产 SHA-256 相同的文件 | 0 命中 | 无测试数据搬运 |

阈值的选择依据与逐条校准过程见 §4.3**（含一次植入式对抗验证）**。

### 4.3 阈值校准记录（为什么这些数字可信）

审计阈值最容易被滥用的地方是"调到通过为止"。本节记录每一次阈值/规则变动的
**证据与理由**，以及一次**植入式验证**，供第三方判断这些数字是否被操纵。

#### 首轮审计结果与逐条处置

首轮审计判定 5 项中 3 项失败。逐条核查后的处置：

| 序号 | 首轮结果 | 核查结论 | 处置 |
| --- | --- | --- | --- |
| 1 | 单文件 containment 最高 13.83%（`ports/common.py`） | 该文件仅 94 个 n-gram、共享 13 个，全部是 `Field(default=0, ge=0)` 这类 pydantic 脚手架。小样本方差，非复制 | 引入**小文件豁免**（n-gram 总数 < 300 不参与 containment 判定），仍列出供人工核验 |
| 1 | `fragment.py` / `session.py` / `source.py` 为 5.05%–5.94% | 共享序列全部是 `@field_validator("summary")`、`value: str) -> str:` 这类**框架语法 + 领域词汇** | 见下"判据重构" |
| 2 | "实质性逐字相同 4 行" | 全部是 `def __len__(self) -> int:` / `def clear(self) -> None:`——Python 数据模型与 Protocol 强制规定的签名，无表达空间 | 分类器新增两条规则：数据模型钩子、Protocol 存根签名（法理：merger doctrine） |
| 3 | 专有标识符"违规" 10 处 | 全部位于 `tests/test_package_integrity.py`，该文件的工作就是**定义与检测**这些词 | 引入自声明标记 `scitrace: independence-guard`，豁免范围可见于报告 |
| 3 | 17 条字符串相似度 ≥ 0.60 | 实际匹配字符数均 < 32，全部是 DOI / URL / 作者名等事实性短串 | 无需改动（`--min-matched-chars 32` 已正确过滤） |
| 3 | `tests/conftest.py` 字符串与上游完全相同（相似度 1.000） | 夹具使用了上游论文的真实作者名与 DOI | **修改夹具为虚构数据**——这是本轮唯一一处真实的内容重合，虽属事实性数据，仍予消除 |
| 5 | 文档 containment 0.10% | 远低于阈值 | 无需处置 |

#### 判据重构：从"统计超标"到"连续片段佐证"

处置序号 1 的后半段时，面临一个选择：把单文件阈值从 5% 调高到 8%（能立刻通过），
还是重构判据。**选择后者**，理由是：调阈值只是把噪声报警器调钝，
而问题本身是**指标没有区分力**。

重构后的判据把"决定性证据"与"统计信号"分开：

- **决定性**：与上游存在 ≥ 25 个 token 的**连续公共片段** → 判失败。
  连续几十个 token 逐字一致无法用"框架趋同"解释，且该判据**不受文件大小豁免**。
- **辅助**：containment 超阈值但无长连续片段 → 通过，但在报告中单列"待复核"，
  并附共享 n-gram 示例供人工判断。

依据是实测：同用 pydantic 表达同一领域概念的两个项目，脚手架序列的随机重合
止步于十余个 token（本项目实测最长公共片段为 **2 行**、**0 个 25-token 片段**），
而真正的整段搬运轻易达到几十至上百个 token。

#### 植入式验证（审计工具自身的有效性检验）

一个恒返回"通过"的审计也能让所有检查变绿。因此做了一次**对抗性验证**：

```bash
# 从上游 HEAD 取一段真实代码，植入本项目，确认审计失败
git -C ../PaperQA show HEAD:src/paperqa/utils.py | sed -n '105,130p' > /tmp/planted_body.txt
cp /tmp/planted.py src/scitrace/_planted_check.py
python tools/similarity_audit.py --target . --reference ../PaperQA --report /tmp/AUDIT_planted.md
```

结果——审计正确检出：

| 检查项 | 植入后 | 本体（无植入） |
| --- | --- | --- |
| 1. n-gram / 最长公共片段 | ❌ 单文件 96.82%，片段 **100** token | ✅ 单文件 13.83%（小文件豁免），片段 **0** |
| 2. 逐行精确复制 | ❌ 实质性 **15** 行，最长对齐 4 行 | ✅ 实质性 **0** 行，最长对齐 2 行 |
| 3. 字符串字面量 | ❌ 违规 **1** 条 | ✅ 违规 **0** 条 |
| 4. 依赖 | ✅ 0 处 | ✅ 0 处 |
| 5. 资产 / 文档 | ✅ 0 个 | ✅ 0 个 |
| **总结论** | **❌ 失败（退出码 1）** | **✅ 通过（退出码 0）** |

这次验证还顺带暴露了判据的一个漏洞：植入内容放在小文件里可以同时躲过
containment 阈值与小文件豁免，使检查项 1 误判为通过。因此把"长连续片段"
确立为**不受豁免的独立判据**——上表已是修正后的结果。

### 4.4 这套验证**不能**证明什么

必须说清楚，否则就是过度宣称：

- 它**不能**证明"思想独立"——方法、流程、架构思想来自公开论文，这是有意为之且公开声明的；
- 它**不能**排除"读过后凭记忆重写"的情况——只能保证结果层面无可测量的文本重叠；
- 它**不能**替代法律意见。

**可以声称的**：本项目代码由作者编写，未复制上游受保护的表达；设计范式来源已公开署名。
